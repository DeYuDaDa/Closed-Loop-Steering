在目前的 `run_experiment.py` 代码逻辑下，采样的过程确实是：
1. **Temperature 缩放**：`logits / temperature`。
2. **Softmax 归一化**：将 Logits 转化为概率分布。
3. **Top-P 过滤**：按概率从大到小排列，保留累加概率达到 0.95 的 Token，其余全部置为 `-inf`。
4. **随机采样**：在剩余的 Token 集合中按概率分布进行 `torch.multinomial` 采样。

### 为什么会出现大量 token 级别重复？

虽然 `top_p` 能过滤掉概率极低的“长尾”噪声，但它在处理“思考模式”（Reasoning/Thinking）时有两个潜在缺陷：

1.  **缺乏 Top-K 的截断**：
    如果 `top_p` 设为 0.95，而模型此时比较“迷茫”，可能会有数百个低概率 token 进入采样池。由于没有 `top_k=20` 的强制限制，随机采样可能会选到一个虽然在 95% 范围内但逻辑并不连贯的 token。一旦选错一个 token，模型为了维持自洽性，很容易陷入自循环（Repetition Loop）。
2.  **缺乏 Min-P 的动态过滤**：
    官方文档推荐 `Min-P` 是因为它是比 `Top-P` 更鲁棒的过滤方式。`Min-P` 会根据**最高概率 Token** 来决定过滤门槛（例如 `p < 0.05 * p_max`）。
    *   当模型信心很强时（$p_{max}$ 很高），`MinP` 会极其严格，效果接近 Greedy Search，防止产生废话。
    *   当模型信心很弱时，`MinP` 会变得宽松。
    而你目前只有 `Top-P`。在思考模式下，模型生成的 `\u21b5`（换行）或重复的逻辑词如果概率分布比较扁平，`Top-P` 可能无法将其有效过滤。

### 改进建议

为了解决重复问题并对齐官方推荐的最佳实践，我建议在采样器中引入 `Top-K` 和 `Min-P`。

    min_p: float = 0.0,   # 新增

    logits_scaled = logits_2d / max(temperature, 1e-6)

### 1. 定量分析：Top-P=0.95 的“长尾噪声”

假设模型正处于一个逻辑推理的关键点（例如你截图中的 math 步骤），此时 Logits 经过 Temperature=0.6 缩放后的概率分布如下：

*   **逻辑主线 Token ($T_{logic}$)**：概率 $P = 0.7$
*   **逻辑备选 Token ($T_{alt}$)**：概率 $P = 0.1$
*   **填充/废话词 ($T_{filler}$)**：
    *   例如 "Let", "me", "so", "Wait"，共 10 个词，每个 $P = 0.01$ (合计 0.1)
*   **词表余下的噪声词 ($T_{noise}$)**：
    *   余下约 100,000 个词，每个词概率极低，平均 $P = 0.000001$。

#### 场景 A：仅使用 Top-P = 0.95
1.  首先选取 $T_{logic}$ 和 $T_{alt}$（累计 0.8）。
2.  为了达到 0.95，采样器必须再吸纳一些低概率 Token。
3.  它会先吸纳所有的 $T_{filler}$（累计加 0.1，达到 0.9）。
4.  **关键点**：为了填补最后 0.05 的缺口，采样器被迫从那 10 万个噪声词中选出几千个加入采样池。
5.  **定量结果**：采样池中不仅有逻辑词，还有 10 个废话词和**数千个完全无关的噪声词**。虽然每一个噪声词概率很低，但它们的概率总和（0.05）足以让你每生成 20 个 token 就会遇到一次“逻辑滑坡”。

#### 场景 B：增加 Top-K = 20
1.  采样器首先将选取的范围限制在概率最高的 20 个词内。
2.  此时采样池只剩下 $T_{logic}, T_{alt}$ 和 10 个 $T_{filler}$ 以及 8 个噪声词。
3.  **定量结果**：即使 Top-P 还没满，那 99,900+ 个无意义词也被物理隔绝了。采样空间一下子从“数千个选项”塌缩回“20 个选项”，**错误生成的确定性大幅增加**。

### 2. 定量分析：Min-P 与“路径发散”的抑制

当你观察到 **Entropy = 0.6** 时，情况更复杂。这意味着模型的分布变得非常“扁平”，可能如下：

*   $P("Let") = 0.3$
*   $P("me") = 0.25$
*   $P("so") = 0.15$
*   $P("Wait") = 0.1$
*   **$P(逻辑正确Token) = 0.05$**
*   其他噪声词合计 0.15

#### 场景 C：仅使用 Top-P = 0.95
在这里，Top-P 几乎没有任何过滤作用，因为前 5 个 token 合计才 0.85。采样器会将那个概率仅 0.05 的正确逻辑词与一堆废话词放在一起权衡。
*   **后果**：你有 80% 的概率采样到填充词，只有 5% 的概率采样到逻辑词。一旦采样到 "Let"，下一轮 "me" 的概率会进一步上升，形成**正反馈闭环**。

#### 场景 D：引入 Min-P = 0.05 (官方推荐设置)
`Min-P` 的逻辑是：保留所有 $P > \text{min\_p} \times P_{max}$ 的 token。
1.  计算门槛：$0.05 \times 0.3 (\text{max prob}) = 0.015$。
2.  过滤：所有概率低于 0.015 的词全部被踢出。
3.  **定量效果**：
    *   虽然模型在犹豫（熵 0.6），但 `Min-P` 识别出 $P=0.05$ 的逻辑词相对于 $P=0.3$ 的最高概率词仍是有意义的，因此保留了它。
    *   但它会瞬间切掉那些概率在 0.01 以下的几万个微弱噪声。
    *   **最重要的是动态性**：如果某一时刻 $P_{max}$ 突然变得很高（比如 0.9），门槛就变成 $0.045$，此时除了大赢家，其他所有词（包括你截图里的重复词）都会被瞬间清场。

### 3. 正反馈风暴：上下文污染

你提到的“上下文污染”可以用**条件概率**来解释：
$$P(T_{n+1} = \text{"me"} \mid T_n = \text{"Let"}) > P(T_{n+1} = \text{"me"} \mid T_n = \text{"Logic\_Step"})$$

1.  **第一步错误**：因为 Top-P 太松，采样到了 "Let"。
2.  **权重偏向**：LLM 的 Attention 模型识别出 "Let"，会显著提高下一步中 "me" 的 Logit 值。
3.  **熵的陷阱**：此时熵可能依然维持在 0.6，因为模型在 "me" 和 "Wait" 之间犹豫。但这已经是一个**低质量的高熵状态**。
4.  **循环固化**：随着序列变成 "Let me. Let me."，这种模式在 KV Cache 中形成了极强的偏置，如果不通过采样器进行“硬剪枝（Hard Pruning）”，仅仅靠 Steering 这种“平滑引导”很难对抗模型内部这种极强的自回归惯性。

**结论：**
如果不加 `Top-K` 和 `Min-P`，你的实验相当于是在一个**有很多破洞的容器**里注入 Steering Vector。哪怕你把模型往正确方向推（Steering），流量也会顺着 Top-P 留下的那 0.05 的“长尾噪声”孔洞泄露出去，变成了你看到的满屏废话。

你观察到的这三个阶段——**异常初现（中高熵） -> 尝试自恢复 -> 频繁复发并熵降（死循环）**——在学术界被称为 **"Degeneration Cascade"（退化级联）**。

我们结合你之前提到的确实参数（`Top-K` 和 `Min-P`），来一步步拆解这个过程，看看为什么缺少这两个参数会成为这场灾难的“帮凶”：

### 阶段一：催化剂（The Catalyst）—— 异常 Token 的首次出现
*   **你的观察**：出现一个语法不对、甚至不太合理的 token，此时熵比较高（0.4-0.6）。
*   **动力学分析**：当熵在 0.4-0.6 时，说明模型在这一步遇到了“分歧点”，没有一个占据绝对主导地位的词，概率分布比较平缓。
*   **缺失参数的致命影响**：因为此时分布平缓，如果你只依赖 `Top-P=0.95`，它会一直向下累加概率，直到把排名极靠后的几十甚至上百个 token 都拉进采样池。那个“不合理”的 token（可能排名第 60，概率只有 0.005）就这样成为了“合法候选项”并被不幸抽中。
    *   **如果此时有 `Top-K=20`**：无论 Top-P 怎么算，这个排名 60 的异常 token 根本连进入采样轮盘的资格都没有，灾难在源头就被掐断了。

### 阶段二：潜伏与复发（The Relapse）—— 模型的自矫正与二次采坑
*   **你的观察**：模型会试图自己回到正确轨迹，但在接下来又预测到了这个异常词。
*   **动力学分析**：LLM 强大的预训练赋予了它一定的“鲁棒性（In-context self-correction）”，所以它尝试无视刚才那个语法错误，继续往下推理。但请注意，那个异常 token 已经**被写入了 KV Cache**。在后续的注意力机制（Self-Attention）中，模型隐式地在给这个异类分配注意力，试图“解释”它的存在。这导致这个异常 token 在后续生成的候选列表中，概率悄悄被“锚定”抬高了（比如从排名 60 升到了排名 30）。
*   **缺失参数的致命影响**：当模型第二次遇到稍微有点犹豫的节点时（哪怕最高概率词很确信），那个被抬高概率的异常 token 再次因为 `Top-P=0.95` 的宽容度混入了采样池。
    *   **如果此时有 `Min-P=0.05`**：由于模型在努力走正轨，大概率有一个绝对正确的词（例如概率 $P=0.6$）。此时 `Min-P` 会立刻划定一条硬性及格线（$0.6 \times 0.05 = 0.03$）。那个异常词虽然被上下文关联抬高了到了 0.02，但依然跨不过 0.03 的门槛，直接被踢出局。**`Min-P` 在这里的作用就是阻止上下文污染带来的“死灰复燃”。**

### 阶段三：死亡螺旋（The Death Spiral）—— 熵的崩塌与自闭环
*   **你的观察**：异常词出现的频率越来越高，熵急剧降低，最后死循环。
*   **动力学分析**：这是 LLM “续写模式”的根本缺陷——**强烈的模式匹配（Pattern Completion）倾向**。当序列中出现了类似于 `[正常] [异常1] [正常] [异常1]` 的结构时，LLM 学到的强大归纳偏置（Inductive Bias）会认为：“哦，这是一篇有特定间隔重复规律的文本！”。
*   **熵为什么会降低？**因为一旦模型“确认”了你在玩重复模式，它就不再生成逻辑了。异常 token $P(异常 | 上下文)$ 的概率开始呈指数级暴涨（达到 0.9 甚至 0.99）。根据熵的公式 $H = -p \log p$，当一个 token 占据压倒性概率时，总熵就会迅速向 0 逼近。
*   **此时参数的影响**：到了这个阶段，再怎么调 `Top-P`、`Top-K` 或 `Min-P` 都没用了（这也是为什么你发现 Anti-Collapse 可能拉不回来）。因为异常 token 本身变成了 Top-1 原住民。

### 1. 从几何到概率：为什么会被“直接带走”？

在 Transformer 的最后一层，Logits 是通过隐藏状态 $h$ 乘上 Unembedding 矩阵 $W_U$ 计算出来的：
$$ \text{Logits} = W_U \cdot h $$

当你施加 Steering（比如用 `critic` 向量 $v$）时，实际的 Logits 变成了：
$$ \text{Logits}_{new} = W_U \cdot (h_{base} + \alpha \cdot v) = W_U \cdot h_{base} + \alpha (W_U \cdot v) $$

*   **平时（低熵状态）**：$W_U \cdot h_{base}$ 中有一个或几个 Token 的值极大，模型很有主见。此时你加上 $\alpha (W_U \cdot v)$，只是给某些特征稍微加点分，不会改变大局，语法依然连贯。
*   **你观察到的时刻（高熵状态）**：模型非常迷茫，$W_U \cdot h_{base}$ 是一片平坦的“草原”。
*   **劫持发生**：因为基础概率扁平，$\alpha (W_U \cdot v)$ 这个外部力就变成了绝对的主导。控制向量 $v$ 里面不仅包含“反思”的抽象概念，它必然还在特征空间中与特定的表面词汇（如 `"Wait"`, `"Let"`, `"But"`, `"Hmm"`）高度绑定。结果就是，**模型根本来不及去“重新查看条件推理”，而是被按着头、机械地输出了向量 $v$ 对应的那个关联词，从而在草原里强行“拔起了一座鹤立鸡群的山峰”。**

### 2. 产生的毁灭性后果：语法断裂与幻觉闭环

你说的**“导致模型产生不符合语法的、不合理的 token”**，正是这种“粗暴注入”的直接后果：
1.  **脱节的强行插入**：模型原本在思考 `2 + 2 = `，遇到高熵（不知道怎么表述过程）。系统强行施加 Critic 向量，模型被逼着输出了一个 `Wait`。此时不仅语法不对，而且上下文逻辑断裂。
2.  **掩耳盗铃式的继续推理**：LLM 本质上是一个单向的“接龙机器”。它看到自己刚写了一个 `Wait`，它**无法**说“哎呀我刚才写错了抹掉重来”。它必须假装这个 `Wait` 是符合逻辑的，并试图把它圆回来（也就是你观察到的“试图回到正确轨迹，此时熵降低”）。
3.  **引鸩止渴**：为了圆这个谎，模型耗费了原本用于解题的注意力，强行编造过渡句（"Let me. Let me."）。当模型发现自己无法用合理的逻辑把上下文串联起来时，最安全、阻力最小的生成路径就是**重复（Repetition）**，从而堕入死循环。

### 3. 这揭示了当前系统的核心悖论

### 方案 1：Entropy-Scaled Steering（EAST 风格）——高熵时自动“轻推”，彻底避免冰面猛打方向盘
**核心思路**：把你当前的 α_t（PD 输出）改成 **entropy-weighted**，高熵时自动衰减干预强度（参考 EAST: Entropic Activation Steering, arXiv:2406.00244）。这直接解决你观察到的“高熵脆弱性”：模型迷茫时，steering 不再鹤立鸡群，而是温和地“提醒”而不劫持。

**数学修补（直接插入模块三 Adaptive Non-linear PD）**：
在计算 α_t 前，加一个 entropy scaling 因子：

\[
\alpha_t' = \alpha_t \cdot \underbrace{\frac{1}{1 + \exp(\lambda_{\text{scale}} \cdot (\text{EMA}_t - \theta_{\text{high}}))}}_{\text{entropy decay}} \cdot \underbrace{\left(1 - \frac{H_t - H_{\min}}{H_{\max} - H_{\min}}\right)}_{\text{normalized entropy weight}}
\]

- \(\theta_{\text{high}} = 0.45\)（你的中高熵阈值）
- \(\lambda_{\text{scale}} = 10\)（可调陡度）
- \(H_t\) = 当前瞬时熵（你 state_monitor.py 已计算）
- 低熵（<0.15）时 scaling ≈ 1（全力推）
- 高熵（0.4–0.6）时 scaling → 0（几乎不推，靠模型自恢复 + ThinkBrake）

**代码插入点**（spherical_injector.py 或 PIDController）：
在 PD 计算完 `u_t` 后、tanh 软截断前插入上面公式。然后把 `α_t'` 传给 SLERP 的 `t` 参数。

**效果**：ThinkBrake 收敛信号 + EAST scaling 配合后，高熵异常 token 出现时，steering 自动“刹车”，模型不会被强塞表面词，退化级联概率大幅下降（EAST 论文实测在决策任务中把 uncertainty 控制得更平稳）。

### 方案 2：Fine-Grained + Token-Aware Steering（AUSteer + CRL + TA-ITI）——只推“关键几个特征 / token”，Steering Less, Achieving More
你现在的 Manifold Projection（PCA）已经很接近，但还是 block-level / 全向量。最新工作证明：**只 steer 少数 task-relevant atomic units（AU）或 SAE features**，就能避免噪声污染（AUSteer: Fine-Grained Activation Steering, arXiv:2602.04428；CRL: Control Reinforcement Learning, arXiv:2602.10437；TA-ITI）。

**数学修补（升级模块二 Manifold Projection + 模块四 Spherical Steering）**：
1. **离线阶段**：在 PCA 后，再用 Sparse Autoencoder（SAE，如果你已有 Gemma Scope 或类似）把 v_manifold 进一步分解成 interpretable features，只保留 top-k（k=5~20）与 “reflection/critic” 最相关的 AU。
2. **在线阶段（token-level）**：在 forward hook 中，只对当前生成的最后一个 token position 做 intervention，且只加到选定的 AU 维度：

\[
h_{\text{new}} = h + \alpha_t' \cdot \sum_{i \in S} (v_i \cdot u_i) u_i
\]

其中 \(S\) = 当前 token 的 misalignment-aware 特征集（TA-ITI 思路：用 token-level entropy + logit margin 计算 misalignment 程度，只对高 misalignment 的 token 启用）。

**代码插入点**：
- state_monitor.py 新增 per-token misalignment score = EMA_t * (1 - ThinkBrake M_t)
- 只在 misalignment > threshold 时触发 Spherical SLERP，且只在选定的 AU 子空间内旋转（保范数依然成立）。

**为什么能修补**：这正是你担心的“关键几个 token 进行干预就能起到很好效果”。全局 steering 容易把 Let/Wait 特征也拉高；fine-grained 只推逻辑主线特征，重复前兆（语法不对 + 中高熵）在阶段一就被精准压制。
